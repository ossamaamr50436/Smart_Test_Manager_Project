🔴 **المرحلة 2: إصلاح التسريب الأمني (حرج جداً)**

**المشكلة:** عند محاولة إنشاء مستخدم ببريد موجود، تظهر رسالة `Unique constraint failed on the fields: (email)` — وهذا يكشف للمهاجم وجود الحساب.

**المطلوب:** في كل مكان تُنشأ فيه مستخدمون (admin-panel-actions.ts، entity-actions.ts، committee-actions.ts، auth-actions.ts)، غلّف استدعاء `prisma.user.create` في try/catch:

```typescript
try {
  const created = await prisma.user.create({ ... });
  return { success: true, userId: created.id };
} catch (error) {
  if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === "P2002") {
    // رسالة عامة — لا تكشف أي شيء
    throw new Error("تعذّر إنشاء الحساب — تحقق من البيانات المدخلة");
  }
  throw new Error("حدث خطأ غير متوقع");
}
```

نفس الشيء لأي جدول آخر فيه `@unique` (email للجهات، serialNumber للشهادات، إلخ).

🔴 **المرحلة 4: تحويل كلمة مرور الجهة إلى رقم التصريح + إجبار التغيير**

**4.1 Schema (تعديل `User`):**
```prisma
mustChangePassword Boolean @default(false)
```

**4.2 Schema (تعديل `Institution`):**
```prisma
managerName    String
supervisorName String
managerPhone   String
supervisorPhone String
licenseNumber  String   @unique
district       String
```

**4.3 عند إنشاء جهة:**
- كلمة المرور = `licenseNumber` (بدون تشفير قبل التخزين — تُشفّر بـbcrypt عادةً).
- `mustChangePassword = true` على المستخدم المرتبط.
- بعد أول تسجيل دخول، يُوجَّه المستخدم قسراً إلى `/change-password` قبل أي شيء آخر.

**4.4 Middleware أو Layout:**

**4.5 صفحة `/change-password`:**
- حقل كلمة المرور الجديدة + التأكيد.
