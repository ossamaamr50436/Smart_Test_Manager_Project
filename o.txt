🔴 المهمة 1: تشخيص Dark Mode (Diagnosis First)

### 1.1 الفحوصات الإلزامية (نفّذها كلها قبل أي تعديل)

**أ) تحقق من Tailwind config:**
```powershell
Get-Content tailwind.config.ts | Select-String -Pattern "darkMode"
Get-Content tailwind.config.js -ErrorAction SilentlyContinue | Select-String -Pattern "darkMode"
```

**ب) تحقق من `.dark` في globals.css:**
```powershell
Select-String -Path "app\globals.css" -Pattern "^\.dark" -SimpleMatch
```

**ج) تحقق من ThemeProvider:**
```powershell
Get-Content "components\providers\theme-provider.tsx"
Get-Content "app\layout.tsx" | Select-String -Pattern "ThemeProvider" -Context 0,10
```

**د) تحقق من package.json:**
```powershell
Select-String -Path "package.json" -Pattern "next-themes|tailwind"
```

### 1.2 الحل حسب السبب

**الحالة A — Tailwind 3.x بدون darkMode: 'class'**:

عدّل `tailwind.config.ts`:
```typescript
const config: Config = {
  darkMode: "class",  // ← الإضافة
  content: [...],
  // ...
};
```

**الحالة B — لا يوجد `.dark` في globals.css**:

أضف في نهاية `app/globals.css`:
```css
.dark {
  --background: 222.2 84% 4.9%;
  --foreground: 210 40% 98%;
  --card: 222.2 84% 4.9%;
  --card-foreground: 210 40% 98%;
  --popover: 222.2 84% 4.9%;
  --popover-foreground: 210 40% 98%;
  --primary: 183 55% 25%;          /* نسخة أغمق من primary الأصلي */
  --primary-foreground: 210 40% 98%;
  --secondary: 40 45% 35%;          /* نسخة أغمق من secondary */
  --secondary-foreground: 210 40% 98%;
  --muted: 217.2 32.6% 17.5%;
  --muted-foreground: 215 20.2% 65.1%;
  --accent: 217.2 32.6% 17.5%;
  --accent-foreground: 210 40% 98%;
  --destructive: 0 62.8% 30.6%;
  --destructive-foreground: 210 40% 98%;
  --border: 217.2 32.6% 17.5%;
  --input: 217.2 32.6% 17.5%;
  --ring: 183 55% 40%;
}

/* انتقال ناعم عند التبديل */
html {
  transition: background-color 200ms ease, color 200ms ease;
}
```

**الحالة C — ThemeProvider لا يمرّر attribute**:

في `app/layout.tsx`، تأكد:
```tsx
<ThemeProvider
  attribute="class"
  defaultTheme={defaultTheme}
  enableSystem={false}
  disableTransitionOnChange={false}
  nonce={nonce}
>
  {children}
</ThemeProvider>
```

### 1.3 التحقق بعد الإصلاح

- شغّل: `pnpm dev -- -p 7777` (أو أي منفذ متاح).
- افتح DevTools → Elements → `<html>`.
- اضغط زر Dark Mode.
- **المتوقع**: `<html class="dark">` (يظهر الـclass).
- **المتوقع**: خلفية الصفحة تصبح داكنة.

🔴 المهمة 2: صفحة إعدادات المنصة لـSUPER_ADMIN

### 2.1 الفحص

**أ) هل `/admin/settings` موجود؟**
```powershell
Test-Path "app\(dashboard)\admin\settings\page.tsx"
```

**ب) ما محتواه؟**
اقرأ `app/(dashboard)/admin/settings/page.tsx` والمكونات المرتبطة.

**ج) لماذا SUPER_ADMIN لا يصل؟**
- في `auth.config.ts`، يوجد `if (role === "SUPER_ADMIN")` → إعادة توجيه كل شيء إلى `/super-admin`.
- هذا يمنع SUPER_ADMIN من الوصول لـ`/admin/settings`.

### 2.2 الحل — خيارَان

**الخيار 1 (موصى به): إنشاء `/super-admin/settings`**

أنشئ المسار التالي: `app/(dashboard)/super-admin/settings/page.tsx`

يحتوي على:
```typescript
import type { Metadata } from "next";
import { redirect } from "next/navigation";
import { getCurrentUser } from "@/lib/actions/auth-actions";
import { requireSuperAdmin } from "@/lib/tenancy";
import { getCachedPlatformSettings } from "@/lib/cache";
import { PlatformSettingsForm } from "@/components/super-admin/platform-settings-form";

export const metadata: Metadata = { title: "إعدادات المنصة" };
export const dynamic = "force-dynamic";

export default async function SuperAdminSettingsPage() {
  const user = await getCurrentUser();
  if (!user) redirect("/login");
  requireSuperAdmin(user);

  const settings = await getCachedPlatformSettings();

  return (
    <div className="space-y-6 animate-fade-in">
      <div>
        <h1 className="text-2xl font-bold">إعدادات المنصة</h1>
        <p className="mt-1 text-muted-foreground">
          الاسم، الشعار، الألوان، والتفضيلات العامة
        </p>
      </div>
      <PlatformSettingsForm initial={settings} />
    </div>
  );
}
```

**مكون `PlatformSettingsForm`**:
- انسخ منطق `components/admin/admin-settings-form.tsx` (موجود) إلى `components/super-admin/platform-settings-form.tsx`.
- استخدم نفس Server Actions الموجودة في `lib/actions/settings-actions.ts`.
- **لا تُنشئ Actions جديدة** — استخدم `updatePlatformSettings` و `updateAppearanceSettings`.

**أضف رابط في Sidebar**:
في `components/dashboard/dashboard-sidebar.tsx`، قسم `SUPER_ADMIN`، أضف:
```typescript
{ href: "/super-admin/settings", label: "إعدادات المنصة" },
```

**الخيار 2 (بديل): السماح لـSUPER_ADMIN بالوصول لـ`/admin/settings`**

في `auth.config.ts`، عدّل قيد SUPER_ADMIN:
```typescript
if (role === "SUPER_ADMIN") {
  const allowedPaths = ["/super-admin", "/admin/settings", "/settings", "/profile", "/notifications", "/settings/tutorial"];
  if (!allowedPaths.some(p => path === p || path.startsWith(p + "/"))) {
    return Response.redirect(new URL("/super-admin", nextUrl));
  }
  return true;
}
```

**الخيار الأفضل**: **الخيار 1** — لأنه يحافظ على الفصل بين SUPER_ADMIN و ADMIN، ويعطي SUPER_ADMIN واجهة مخصّصة.

### 2.3 التحقق

- اذهب إلى `/super-admin` (كـSUPER_ADMIN).
- اضغط على **"إعدادات المنصة"** في Sidebar.
- عدّل الاسم والشعار.
- **المتوقع**: يُحفظ التغيير وتظهر النتيجة.
