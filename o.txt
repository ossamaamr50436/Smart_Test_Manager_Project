🔴 المهمة 1 (الأهم): إصلاح زر تسجيل الدخول — يحتاج ضغطات متعددة

**المشكلة الوصفية:**
- المستخدم يضغط زر "دخول".
- لا يحدث شيء.
- يضغط مرة ثانية → يبدأ التحميل.
- يضغط مرة ثالثة → يدخل.
- **هذا يشمل زر الدخول وأي زر في النماذج.**

**التشخيص المطلوب (تحليل شامل):**

1.1 **في `components/auth/login-form.tsx` (أو ما يعادله):**
- اقرأ الكود كاملاً.
- ابحث عن:
  - `useTransition` أو `useState(loading)` أو `useFormStatus`.
  - `preventDefault()` في `onSubmit`.
  - `disabled` على الزر.
  - `signIn()` من `next-auth/react` أو Server Action.
  - `router.push` بعد النجاح.

1.2 **السبب الأكثر ترجيحاً (بناءً على التاريخ):**
- **مشكلة Hydration** في Next.js 14: الزر لا يكون interactive حتى ينتهي Hydration.
- الحل: **`useFormStatus` + `<form action={serverAction}>`** بدلاً من `onSubmit` اليدوي.
- أو: **`useTransition` + Server Action مباشر**.

1.3 **في `lib/actions/auth-actions.ts` (أو ما يعادله):**
- إذا كان `signIn` يُستدعى من Server Action → تأكد أنه لا يُعيد التوجيه بطريقة خاطئة.
- إذا كان من `next-auth/react` → استخدم `redirect: false` ثم `router.push` بنفسك.

1.4 **في `app/(auth)/login/page.tsx`:**
- تأكد أن الصفحة **Server Component**.
- تأكد أن `LoginForm` هو **Client Component** فقط.
- إذا كانت الصفحة بأكملها Client Component → هذا سبب مشكلة Hydration.

1.5 **الحل المعتمد:**

```typescript
// components/auth/login-form.tsx
"use client";

import { useState, useTransition } from "react";
import { signIn } from "next-auth/react";
import { useRouter } from "next/navigation";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

export function LoginForm() {
  const router = useRouter();
  const [isPending, startTransition] = useTransition();
  const [error, setError] = useState("");

  async function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault();
    if (isPending) return; // منع الضغط المزدوج

    const formData = new FormData(e.currentTarget);
    const email = formData.get("email") as string;
    const password = formData.get("password") as string;

    startTransition(async () => {
      setError("");
      try {
        const result = await signIn("credentials", {
          email,
          password,
          redirect: false,
        });
        if (result?.error) {
          setError("البريد الإلكتروني أو كلمة المرور غير صحيحة");
        } else {
          router.push("/");
          router.refresh();
        }
      } catch {
        setError("حدث خطأ — حاول لاحقاً");
      }
    });
  }

  return (
    <form onSubmit={handleSubmit} className="space-y-4">
      <div>
        <Label htmlFor="email">البريد الإلكتروني</Label>
        <Input
          id="email"
          name="email"
          type="email"
          required
          autoComplete="email"
          disabled={isPending}
        />
      </div>
      <div>
        <Label htmlFor="password">كلمة المرور</Label>
        <Input
          id="password"
          name="password"
          type="password"
          required
          autoComplete="current-password"
          disabled={isPending}
        />
      </div>
      {error && <p className="text-sm text-destructive">{error}</p>}
      <Button type="submit" disabled={isPending} className="w-full">
        {isPending ? "جارٍ الدخول..." : "دخول"}
      </Button>
    </form>
  );
}
```

**ملاحظات الحل:**
- `disabled={isPending}` يمنع الضغط أثناء المعالجة.
- `startTransition` يجعل الزر interactive قبل Hydration.
- `redirect: false` + `router.push` يعطي تحكماً كاملاً.
- لا يوجد `loading` state مزدوج.

1.6 **تحقق إلزامي:**
- افتح `/login` في متصفح نظيف.
- اضغط "دخول" **مرة واحدة فقط**.
- المتوقع: يبدأ التحميل فوراً → يدخل.
- **لا يحتاج ضغطاً ثانياً**.

1.7 **نفس المنهج طبّقه في:**
- كل نماذج `components/**/*form*.tsx`.
- كل نماذج `components/**/*manager*.tsx` (الأزرار النهائية).
- تأكد أن كل `<Button type="submit">` له `disabled={isPending}`.

🔴 المهمة 2: إلغاء إجبار تغيير كلمة المرور للمستخدمين المُنشَأين من الأدمن

**المشكلة:**
عندما ينشئ الأدمن مستخدماً جديداً، النظام يضبط `mustChangePassword: true` — فيُجبَر المستخدم على تغيير كلمة المرور عند أول دخول.

**المطلوب:**
- **إلغاء هذا السلوك** للمستخدمين المُنشَأين من الأدمن.
- كلمة المرور التي يضعها الأدمن تبقى **فعالة دائماً**.
- الأدمن يستطيع **التحكم يدوياً** بإجبار التغيير إن أراد (خيار في النموذج).

**التنفيذ:**

2.1 **في `lib/actions/admin-panel-actions.ts` (دالة `createAdminUser`):**
- احذف `mustChangePassword: true`.
- غيّره إلى `mustChangePassword: false` (افتراضياً).
- أضف معاملاً اختيارياً `forcePasswordChange?: boolean` في `input`.
- إذا `forcePasswordChange === true` → `mustChangePassword: true`، وإلا → `false`.

```typescript
export async function createAdminUser(input: {
  name: string;
  email: string;
  password: string;
  role: string;
  birthDate?: string;
  institutionId?: string;
  forcePasswordChange?: boolean; // ← جديد
}): Promise<CreateUserResult> {
  // ...
  created = await prisma.user.create({
    data: {
      // ...
      mustChangePassword: input.forcePasswordChange === true, // ← الافتراضي false
    },
  });
  // ...
}
```

2.2 **في `components/admin/admin-users-manager.tsx`:**
- في نموذج الإنشاء، أضف Switch اختياري:
  ```
  [ ] إجبار المستخدم على تغيير كلمة المرور عند أول دخول
  ```
- افتراضياً غير مفعّل.
- أرسل `forcePasswordChange` في بيانات الإنشاء.

2.3 **في `auth.config.ts` (منطق middleware):**
- تأكد أن `mustChangePassword: false` **لا** يُوجّه إلى `/change-password`.
- إذا كان المنطق يعتمد على قيمة أخرى، أصلحه.

2.4 **اختبار إلزامي:**
- كأدمن → أنشئ مستخدماً جديداً (بدون تفعيل Switch).
- سجّل دخول بالحساب الجديد.
- **المتوقع**: يدخل مباشرة إلى لوحة دوره — **لا يُوجَّه إلى `/change-password`**.
- ثم كأدمن → أنشئ مستخدماً آخر مع تفعيل Switch.
- سجّل دخول به → **يُوجَّه إلى `/change-password`**.

🔴 المهمة 3: إصلاح خطأ تغيير كلمة المرور الإلزامية

**المشكلة**: عند تغيير كلمة المرور، إذا:
- المستخدم أدخل كلمة جديدة = الحالية
- أو كلمتان غير متطابقتين
- أو كلمة ضعيفة

يظهر خطأ إنجليزي طويل.

**المطلوب:**

3.1 حوّل `changeMyPassword` في `lib/actions/change-password-actions.ts` إلى union:
```typescript
export type ChangePasswordResult =
  | { success: true }
  | { success: false; error: string; fieldErrors?: Record<string, string> };
```

3.2 التحققات بالترتيب:
- كلمة المرور الحالية مطلوبة → "كلمة المرور الحالية مطلوبة"
- الجديدة تطابق `passwordSchema` → "كلمة المرور ضعيفة"
- الجديدة = الحالية → "كلمة المرور الجديدة يجب أن تختلف عن كلمة المرور الحالية"
- الجديدة ≠ التأكيد → "كلمتا المرور غير متطابقتين"
- كلمة المرور الحالية خاطئة → "كلمة المرور الحالية غير صحيحة"
- نجاح → `{ success: true }`

3.3 في `components/auth/change-password-form.tsx`:
- اعرض `result.error` كنص عربي.
- استخدم `useTransition`.
- عطّل الزر أثناء `isPending`.
